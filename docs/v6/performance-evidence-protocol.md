# 实际产品性能证据（测量前登记）

本协议在正式100次性能测量前登记。它区分真实产品请求与真实供应商调用，不改15秒/45秒的p95、至少100次请求或600次真实模型实验的门槛。

用户批准A1/B可在质量达标时成为默认，乐乐仍用于解释与追问。规则默认路径若没有必要的模型操作，真实HTTP请求和浏览器渲染属于`real_product`证据。不能为了取得`live_model`标签强行添加产品本来不会发出的调用；也不能把mock响应、直接函数调用或测试夹具计入实际首屏延迟。`actualModelRuns`仍只接受`live_model`。

正式记录绑定候选构建、目录、算法和完整模型配置哈希。使用生产构建、实际PostgreSQL、浏览器实际消费API响应；关闭mock和测试捷径。首屏须出现可识别的具体决策（竞赛与个人依据），加载骨架不算。完整报告以该次实际显示列表和全部必需字段完成渲染为止，报告不足5项仍须呈现真实原因。单调时钟从用户触发生成记录到各渲染事件，服务器耗时只作辅助。记录设备视口、成功/失败、回退、响应状态和真实报告摘要哈希。

样本矩阵为预先冻结的至少60个不同模拟画像，桌面与移动各50次请求，共100次；快速和深入流程均覆盖。不得看延迟后剔除慢样本或重跑取最快值；失败与超时保留分母并单列，缺少首屏/报告事件使该项性能结果不可通过。最近秩p95取升序第ceil(0.95N)个。冷/热请求和缓存命中分别记录，首个请求不丢弃。此矩阵不证明真实学生耗时。

若选择C，正式性能请求须按冻结配置调用Flash/max，所有实际费用走同一预算账本。A1/B的真实产品测量不替代C调用实验，也不证明画像自由文本抽取或付费问答的延迟。不同模式分别记录，不能把A1数据改标成C。降档仍须按原质量优越性实验门槛。

门禁新增`real_product`证据类别仅适用于首屏与完整报告性能；普通单测仍为`deterministic`，不可因此通过性能门槛。最终证据还须通过原始浏览器记录的聚合校验，手填一个数字与文件哈希不构成已测性能。

原始证据派生还核对以下绑定：浏览器保存收到最终报告时的单调时钟`responseAt`，首屏/完整报告不能早于该时刻，也不能早于HTTP响应相对确认点击的耗时（仅允许5毫秒时钟精度差）。报告须通过完整V6合同；选定A1/B/C分别对应rules/hybrid/llm的运行配置和实际trace。C或B发生规则回退须保留明确fallback原因，不能把规则运行改标成另一算法。当前生产路由尚未接入B，离线B实验不能作为产品B性能证据。

正式测量前须等待已有调用结算。前后PostgreSQL只读原始快照保留全部历史行、authority、资金上限和budget配置；既有行任何字段改变都使这组性能证据无效，新主run usage行按固定价表重新计价。该限制避免把其他并发结算混入本轮差额。候选构建的BUILD_ID、build-manifest、required-server-files和生成的next-env原字节也必须保存，源码/配置前后摘要一致。这里的结构与连续性校验不能替代独立复核实际执行来源。

原始服务器日志同时保存按HTTP请求ID关联的`competition_accounting_trace`，仅记录占用、实际派发与结算事件的允许字段，不包含密钥、提示词或学生原话。浏览器报告的`X-Request-ID`须唯一匹配这些事件，再逐次关联本轮新增PostgreSQL占用行；旧行、重复占用、次数或状态矛盾均拒绝。结算失败保留全额占用及失败事件，未知用量保持unknown；未知价表保持pending，不能用零费用或手填金额替代。公开报告只有全部用量已知时才展示可核对的token和费用合计。这些绑定是证据完整性检查，不证明该模型已经通过质量门槛。

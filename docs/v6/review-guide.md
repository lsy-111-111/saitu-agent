## 建立可审查画像

每个正式画像要有具体的目标、任务偏好、本人贡献、可投入时间与限制，以及信息来源。经同意使用去标识真实访谈，或由独立领域评审设计并审核；明确区分两者。不得只改姓名、专业标签或措辞便计作独立画像。记录 familyId，把相关变体留在同一数据分组。

六组为软件与数据、工程设计、实验与农业、商业实践、调查与教育、艺术与语言。重点是低年级与新手，同时覆盖有课程作品、没有奖项、低预算、无导师、跨专业、时间不足和目标冲突。细分专业覆盖不等于统计上证明所有专业均有效。

## 独立评分

评审者先看确认画像与相同版本的官方/编辑资料，不看算法名、排名、其他评审结果或商业推广。按打乱顺序的统一候选池逐项打分：

| 相关度 | 判断 |
|---|---|
| 3 | 服务主要目标，有明确任务连接与可行条件 |
| 2 | 有价值的次选或准备路线，差距与条件可解释 |
| 1 | 弱相关探索，目标联系有限或关键条件待定 |
| 0 | 已知不合格、任务冲突、违反限制或无可行投入路径 |
| U | 证据不足，不能判断；不能填0代替 |

另记目标价值、任务/经验支撑、可行性、差距/收益解释、行动性五维0–4分。每条写支持的学生事实与竞赛事实ID和一条判断理由。能力只能来自自述/具体经历；兴趣不升级为熟练度，团队奖项不升级为个人独立贡献。

两名评审独立完成后保留原始表，计算裁决前的一致性，再由第三人处理分歧。无法解决的规则冲突标U和待核实，不强造唯一答案。候选池全部完成后才能算共同IDCG；算法结果新增未审候选时，在查看优劣分数前补审并重新冻结。

## 来源复核

资格、组别、日期、费用、交付物与奖项必须核对主办方适用年份、赛道和段落。学校转发适用本校的选拔条件不能扩大为全国规则。编辑估算的工作量、成长价值与建议要与官方事实区分。当前不能报名不意味着没有未来准备价值，但报告必须明确区分。

## 封存与失败处理

独立人员保存正式标签、资料快照、配置与哈希。开发者不拿封存答案反复调参；验收失败后旧集转回归，新增独立材料再验收。不得删除难题、把未标注当无关、将自己或模型的审阅签为独立多人审核。
